# 단어 개편 — 어절·하이라이트 기계 검수

2026-10-07 최종 기계 검수에 사용한 `audit_v2.py`입니다. 검수 로직은 유지하고 입력 파일, 출력 폴더, 원본 탭 URL을 실행 옵션으로 분리했습니다. 이 폴더에는 코드와 사용 설명만 포함합니다. 원본 콘텐츠, 사전 데이터, 검수 결과 및 AI 프롬프트는 포함하지 않습니다.

## 검사 범위

1. **어절 전체 누락·추가·중복**: 원문과 추출 어절을 순서대로 비교합니다. 비교할 때 공백과 Unicode `P*` 문장부호를 제거합니다. 합친 글자가 같으면 띄어쓰기·문장부호·행 경계 차이는 제외합니다. 어절 배열 정렬에는 `difflib.SequenceMatcher(autojunk=False)`를 사용합니다.
2. **하이라이트 존재 여부**: 하이라이트가 비어 있거나 해당 어절의 연속 문자열이 아니면 검출합니다. 이 검사는 공백·문장부호를 정규화하지 않습니다.

예: `내가`의 하이라이트가 `나`이면 실패, `내`이면 통과합니다. `내가`도 존재 검사에서는 통과하므로 의미상 올바른 범위까지 보장하지 않습니다.

### 검사하지 않는 것

- 표제어의 문맥상 정답, 품사·사전 뜻 매핑, 하이라이트의 의미상 범위
- 구 병합의 정확성, 이전 탭과의 차이·삭제 이력
- 교체 구간이나 글자 일부 변형: 전체 어절 누락·추가로 확정하지 않고 집계의 `excluded_replacement_sentences`에 기록합니다. 해당 문장을 정상으로 판정한다는 뜻이 아닙니다.
- 모든 행이 사라진 문장: 대상 탭에 남아 있는 문장을 기준으로 하므로 외부 원문 목록 없이 검출할 수 없습니다.

## 실행

Python 3.9 이상, 표준 라이브러리만 사용합니다. API 키·AI 호출·추가 패키지는 필요 없습니다.

```powershell
python audit_v2.py "C:/data/source.xlsx" --output-dir "C:/data/audit-output"
```

결과에 원본 행 링크를 넣으려면 **원본 탭의 URL**을 전달합니다. 기존 `range` 매개변수가 없는 `#gid=숫자` 형태를 사용합니다.

```powershell
python audit_v2.py "C:/data/source.xlsx" --output-dir "C:/data/audit-output" --source-sheet-url "https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit#gid=YOUR_SHEET_ID"
```

입력 파일은 읽기만 하며 Google Sheets에 쓰거나 수정하지 않습니다. 같은 출력 폴더로 실행하면 같은 이름의 결과 파일을 덮어씁니다. 이전 실행의 청크가 남지 않도록 실행별 출력 폴더를 사용하세요.

## 입력 형식과 제한

이 코드는 당시 Google Sheets에서 내려받은 XLSX 구조에 맞춰져 있습니다. ZIP 내부의 **`xl/worksheets/sheet2.xml`**을 읽습니다. 탭 이름으로 선택하지 않으므로 대상 탭이 이 XML에 해당하는지 확인해야 합니다. `xl/sharedStrings.xml`과 `xl/styles.xml`이 필요하며 임의의 XLSX 생성기와의 호환성은 보장하지 않습니다.

첫 행은 아래 헤더, A:S는 아래 순서여야 합니다.

| 열 | 필드 | 열 | 필드 |
|---|---|---|---|
| A | # | K | 하이라이트_텍스트 |
| B | 콘텐츠_SN | L | 구_그룹ID |
| C | 콘텐츠_유형 | M | 사전_표제어 |
| D | 레벨 | N | 품사 |
| E | 제목 | O | 어휘_등급 |
| F | 문장_순서 | P | 사전_뜻풀이 |
| G | 문장 | Q | 영어_대역어 |
| H | 어절_순서 | R | 영어_뜻풀이 |
| I | 어절 | S | 매핑_여부 |
| J | 표제어 | | |

문장 키는 `콘텐츠_SN + 콘텐츠_유형 + 문장_순서`입니다. 같은 키의 G열 원문이 일관되고 H열이 정수라는 전제하에 H열 순서대로 비교합니다. 이 전제 자체는 별도로 검증하지 않습니다. 숫자는 당시 파일에서 사용한 일반 숫자·정수 백분율·소수 둘째 자리 백분율·천 단위 구분 형식을 복원하며 모든 사용자 지정 숫자 형식을 지원하지는 않습니다.

## 출력

| 파일 | 내용 |
|---|---|
| `v2_report.json` | 헤더를 포함한 2차원 배열. 오류 유형, 기대값, 현재값, 조치, 원문, 식별자, 행 위치, 판정 근거, 원본 링크 |
| `v2_meta.json` | 대상 행·문장 수, 오류 유형별 건수, 제외된 교체 구간 문장 수, 입력 파일 SHA-256 |
| `v2_chunk_000.json` 등 | 시트 업로드용으로 250행씩 나눈 결과. `start`는 헤더 포함 0-based 시작 위치 |

콘솔에는 집계와 앞 8개 사례를 출력합니다. 생성된 파일과 로그에는 입력 콘텐츠가 포함되므로 이 공개 저장소에 올리지 않습니다. 시트 업로드 코드는 포함하지 않습니다.

## 개발자 처리 순서

1. 어절 추가·중복을 원문과 대조해 정리하고, 누락 어절을 복구합니다. 동일한 정상 행의 값은 보존합니다.
2. 해당 문장의 어절 순서를 다시 부여한 다음 하이라이트 검수를 재실행합니다. 삭제한 행의 하이라이트 오류를 다시 고칠 필요는 없습니다.
3. 어절까지 빈 행인지 먼저 확인합니다. 유효한 어절의 하이라이트만 채우고, 새로 만든 어절의 표제어·하이라이트는 별도로 추출합니다.
4. 같은 규칙으로 재검수한 후, 문맥이 필요한 표제어·하이라이트·사전 매핑 검수는 별도 단계로 진행합니다.

**위치 해석:** 누락은 실제 행이 없으므로 해당 문장의 기존 행들을 표시합니다. 기대값과 앞뒤 어절을 보고 삽입 위치를 정하세요. 추가·중복은 연속 구간을 1건으로 묶습니다. 행 번호와 링크는 검수 당시 위치이므로 실제 수정 시 `#` 및 문장 키를 대조해야 합니다. 어절 오류와 하이라이트 오류 건수는 중복될 수 있습니다.
